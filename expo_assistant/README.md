# Qwen 本地工作台

复用当前 Qwen3.6-27B AWQ4 + DFlash 服务的多模态 Agent harness。浅色工作台提供会话历史、附件预览、工具过程、天气卡片与按需展开的性能面板。侧栏保留体验案例和最近对话，不展示项目文件目录。不会加载第二份模型。

## 启动

当前已部署机器从模型到工作台的完整启动顺序见 [本机启动指南](../启动指南.md)，日常使用优先通过已有用户服务启动。

先启动本项目 vLLM 服务，然后在仓库根目录运行：

```bash
bash expo_assistant/run.sh --upstream http://127.0.0.1:8000 --model Qwen3.6-27B-AWQ4
```

打开 **http://127.0.0.1:8088**。启动器在 `.runtime/harness-venv/` 安装独立的 Pillow、pypdf、lxml 依赖，不修改推理容器。当前固定依赖需要 Python 3.11+。前端无构建步骤、CDN、外部字体或 Node 依赖。

也可以沿用本机入口：

```bash
bash scripts/strix_halo.sh harness dflash
```

当前机器已经使用 `qwen-strix-expo.service` 用户服务运行工作台。管理命令：

```bash
systemctl --user status qwen-strix-expo.service
systemctl --user restart qwen-strix-expo.service
journalctl --user -u qwen-strix-expo.service -n 40
```

用户服务随用户登录启动；模型容器仍按项目原有流程启动。若该服务已占用 8088，请勿同时启动第二个前台实例。

## 三种模式与四个体验案例

| 模式 | 可用能力 |
| --- | --- |
| 对话 | 多轮问答、图片理解、上传文档全文搜索与分段阅读；不访问项目文件或联网 |
| Agent | 项目目录浏览、按行读文件、内容搜索、创建/编辑文件、附件搜索与分段阅读 |
| 搜索 | 公开网页搜索、网页正文与链接读取、城市天气；同时可读取项目与附件，不修改文件 |

左侧 **体验新能力** 可以直接载入问题和配套素材，确认输入后点击发送。首页三个卡片也链接到对应案例。每个案例有可展开的校验点和后续任务按钮。

| 案例 | 实际动作 | 校验点 |
| --- | --- | --- |
| 项目文件读写 | 读 `harness-demo/brief.json` 与会议记录，写入 `harness-demo/checklist.md` | 3 项任务，1 项已完成、2 项待完成；后续可修改单项负责人 |
| 图片与文档理解 | 自动附上柱状图 PNG 与目标文档 TXT，走真实视觉接口 | 每天 32 / 46 / 41 / 59 / 72，合计 250，距离目标 260 差 10 |
| 联网搜索与引用 | 搜索 vLLM 前缀缓存官方文档，打开原网页并引用 | 工具记录含 `web_search`、`fetch_page`；区分 prefill 和 decode |
| 城市天气查询 | 查询北京当前天气及从今天起 3 天预报；可以修改城市 | `get_weather` 返回城市、时间、温度、降水概率和来源，页面显示天气卡片 |

项目样例只在首次载入时创建，不覆盖已经存在的样例文件。`harness-demo/` 和实际输出均忽略 Git；素材源文件在 `examples/`。图片案例的答案仅用于界面校验，不会塞入模型提示词。

## 文件与附件

- Agent 通过工具浏览和读写项目；展开文件工具卡片后，点击“查看”可以预览、下载、交给模型阅读，也可在预览窗中手动编辑保存。
- 使用附件按钮、拖入文件或粘贴图片。单个附件最多 12 MiB，每次最多 4 个附件，其中最多 2 张图片。
- 图片支持 PNG/JPEG/WebP/GIF/BMP。传给模型的副本按长边 1280 像素缩放、转为 JPEG；GIF 取首帧。原附件保存在本地。
- PDF、DOCX、XLSX、PPTX 提取文字/单元格值，UTF-8 文本、Markdown、CSV、JSON 和源码直接读取。不执行宏或电子表格公式。
- PDF 限 150 页；扫描 PDF 没有文字层时，提示上传页面图片进行视觉理解。PDF/Office 内嵌图表不会自动变成视觉输入。
- 文档最多提取 20 万字符，初始问题提供前 6000 字符摘录。三种模式均可调用 `search_attachment` 定位关键词和页码，再用 `read_attachment` 分段读取。追问、切换模式后仍可访问当前会话的文档，无需重复上传。工具卡片显示实际读取的页码并可打开原文。
- 每会话最多 24 个附件、总计 64 MiB。超出后可新建会话。会话和附件不自动上传到推理以外的云服务；联网工具会把查询关键词或城市发送给相应服务。

默认工作区是本仓库，可在启动时更改：

```bash
bash expo_assistant/run.sh --workspace /path/to/project --data-dir /path/to/local-harness-data
```

文件工具只操作该工作区的相对路径，不跟随符号链接，不访问 `.git`、`.env*`、密钥文件、权重及运行时缓存目录。已有文件必须先读，写入时校验 SHA-256 防止覆盖其他修改；变更前内容和 diff 存在数据目录的 `changes/<change_id>/`。取消任务不会撤销已成功的文件修改，可展开工具卡片确认实际结果。当前没有任意 shell/代码执行工具。

## 搜索与天气

`web_search` 读取 Bing / 搜狗公开搜索页，返回真实标题、摘要和来源地址。一个来源受限或结果偏题时自动尝试另一来源，并保留型号/版本等关键词缩短查询；返回实际查询词、来源、尝试过程与匹配状态。遵守 `site:` 域名约束，不用相近型号冒充目标型号。一次查询最多 30 秒，可取消。公开搜索页仍会受访问限制、索引覆盖和页面结构影响；仅找到相近内容时明确标记，不能保证所有关键词都有可用结果。

`fetch_page` 读取 HTML/文本/JSON。单页读取上限 16 MiB，返回正文上限 12,000 字符；可传简短 `query` 定位正文片段、表格、页面内嵌 JSON 参数和相关链接，避免大参数总表只返回页首导航。它只解析资料，不运行网页 JavaScript。每次连接和重定向检查公开 IP，并将连接固定到已检查的地址，不访问 localhost、内网和云元数据地址。页面内容按资料处理，不能改变工具权限。

`get_weather` 使用 [Open-Meteo 预报 API](https://open-meteo.com/en/docs) 和[城市查询 API](https://open-meteo.com/en/docs/geocoding-api)。支持从今天起 1–7 天，返回明确地点、本地数据时间、时区、当前天气和每日最高/最低温及降水概率。当前天气来自数值预报，界面会标明来源。没有城市时模型应先询问，不能用本机时区推断用户位置。

如已订阅 Open-Meteo 客户服务，可为服务进程设置 `OPEN_METEO_API_KEY`，自动选择其 customer endpoints。服务使用范围遵循数据提供方条款。模型 API key 使用 `QWEN_API_KEY`；密钥只在服务端使用。

## 会话与 Agent 执行

新页面使用 `/api/agent`，由服务端维护可信的工具调用历史。默认最多 8 次模型调用、16 次工具执行，最后一步强制总结；每步输出上限可在输入框右侧修改。工具参数截断时不执行。正文因输出上限截断时，剩余预算内最多自动续写两次，仍未结束则显示“回答尚未结束”和继续按钮，不标为已完成。续写使用 vLLM 的 `continue_final_message=true` / `add_generation_prompt=false`，接在同一条助手消息后，避免新建助手轮次导致重复开头。

最新信息查询使用当前系统日期。连续 3 次联网工具失败后提前进入总结，最终总结请求不再提供可调用的工具。如果模型返回空正文，工作台展示已取得的原始来源片段和失败原因，标注为工作台提示与未完成，避免只剩一句“提高输出上限”。这份保底提示不是模型完成的分析。

若模型只输出附件函数代码而没有实际调用，服务会要求一次正式工具调用；仍失败则明确报错。代码文本本身不会被当作可执行工具，用户明确请求代码示例时也不会触发此纠正。

工具过程通过 SSE 实时显示，支持停止。模型流结束、工具修改与取消均记录状态；中止后成功执行的操作继续保留。会话、工具记录和附件保存在默认 `.runtime/harness/`，浏览器只保存最近会话 ID，刷新后可以继续。长文优先调用同一推理服务的 `/tokenize`，按实际模板和工具计数并预留输出空间；预算不足时按完整用户轮次裁减，必要时缩短较早工具结果，页面会提示，原始记录保留。计数接口不可用时退回保守长度限制并提示。

最近对话的每行右侧有删除按钮，确认后移除该会话记录及仅属于它的上传附件，保留项目文件和文件修改备份。当前有任务运行时不能删除。删除当前会话后自动打开剩余会话；没有剩余会话则新建空白对话。API 为 `POST /api/session/delete`，请求体 `{"session_id":"…"}`，同样检查来源、主机名和运行状态。操作无法撤销。

旧 `/api/chat` 保留 Responses/Chat 协议与现有测速脚本兼容。新 Agent 固定走 Chat Completions 工具接口，要求推理服务启用自动工具选择和匹配的工具解析器。本机已启用 `--enable-auto-tool-choice --tool-call-parser qwen3_coder`。

服务默认仅监听 `127.0.0.1`，是单机工作台，不带多用户登录体系。`--host 0.0.0.0` 会改变访问范围，不会自动增加认证。

## 性能数字

Agent 的整个任务可能包含多次模型调用。顶部 **性能** 面板中的 Prefill、Decode、首输出和输入/输出 token 对应**最后一次模型调用**；任务总耗时包含全部模型调用和工具执行，说明文字会给出调用次数。

- Prefill：优先使用服务端实际计算的 KV token 数除以 prefill 阶段时间，排除已缓存的前缀。
- Decode：`(output_tokens - 1) / decode_seconds`，排除 prefill 阶段产生的首 token。
- 每步单独抓取并核对 `/metrics` 差分。检测到其他客户端混入、usage 不匹配、指标不完整或全部缓存命中时，相关速率显示 `—`。
- 不按字符、流式片段或工具文本估算 token；不把整个 Agent wall time 当作 decode 速度。

`--demo` 仅用于界面预览，使用模拟文本，不调用模型或提供测速；正式使用应去掉该参数。
